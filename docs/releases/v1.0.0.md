# AEWS v1.0.0

AEWS v1.0.0 is the first stable release of the AI Engineering Workspace
Standard: a minimal way for Codex, Claude Code, and future agents to consume one
reviewed project context without duplicating project knowledge in tool-specific
instruction files.

## Highlights

- Stable four-scope and canonical-document model.
- Thin adapter contract with Codex and Claude Code as primary compatibility
  targets and an open extension path for other tools.
- Optional evidence-backed cross-agent checkpoint protocol using shared
  Project, Decisions, Handoff, task, Git, and test evidence.
- Dependency-free, read-only validator with template and adoption modes.
- Routing-only `aews.json` mapping and reusable adoption template.
- Three anonymized real-repository evaluations.
- Controlled runtime-loading evidence for Codex CLI `0.145.0` and Claude Code
  `2.1.218` against the same synthetic checkpoint.

## Start Here

- Follow the Quick Start in `README.md` for a new or existing repository.
- Use `docs/adoption-guide.md` for migration decisions.
- Copy `templates/adoption/aews.example.json` when existing canonical documents
  already own the AEWS roles.
- Run `python3 scripts/aews_validate.py <target-repo> --mode template` for a
  preferred-filename repository, or adoption mode with a mapping.

## Compatibility Boundary

Runtime evidence is scoped to the recorded versions and configurations. AEWS
provides checkpoint continuity, not live presence, file locking, transcript
sync, hooks, MCP catalogs, memory runtimes, or agent orchestration.

## Upgrade From v0.1.0

Existing thin adapters remain valid. Adopters may optionally add the shared
checkpoint protocol and `aews.json` mapping. Review `docs/versioning.md` and
`CHANGELOG.md` before changing validation expectations.

The full release audit is recorded in
`docs/releases/v1.0.0-readiness.md`.
