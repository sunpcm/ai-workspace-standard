## v1.0 Readiness

The local architecture and migration surface satisfies three of the four v1.0
exit criteria:

- users can adopt AEWS from the README, adoption guide, and mapping template;
- breaking changes have a versioning policy and changelog;
- adapters remain projections and the validator checks their routing.

The remaining v1.0 blocker is repeatable runtime-loading evidence for Claude
Code. The fixture is public and synthetic, but sending it to the external
Claude service still requires explicit owner approval. Until that probe passes
and its version-scoped evidence is recorded, AEWS must not claim v1.0-ready
primary-tool compatibility.

## Owner-Controlled Publication Steps

After reviewing the candidate and authorizing publication, the owner may:

1. confirm the branch is clean and select the release commit;
2. push the local commits;
3. tag `v0.2.0`;
4. publish release notes based on `CHANGELOG.md`;
5. separately authorize the one Claude runtime probe before considering v1.0.

This audit intentionally performs none of those external or irreversible
steps.
