# AEWS v1.1.1

AEWS v1.1.1 is a documentation and repository-policy release. It changes no
acceptance rule: `scripts/aews_validate.py` is untouched, so every repository
that passed under v1.1.0 still passes unchanged.

## Highlights

- A Simplified Chinese README translation at `README.zh-CN.md`, linked from the
  English original.
- A documentation language policy, enforced by
  `tests/test_language_boundary.py`. A document stays English when the
  validator compares it, or when it is published outside the repository or
  needed to adopt AEWS. Other documents may use the maintainer's language, and
  other languages otherwise arrive as `<name>.<lang>.md` translations.
- Wider privacy scans in `docs/release-checklist.md`, which previously missed
  `README.zh-CN.md`, `CONTRIBUTING.md`, `tests`, and `.github`.
- Release records that stand on their own: `docs/releases/v1.1.0-readiness.md`
  now restates its release-classification rationale instead of only linking to
  it, and `README.md` lists the limits on the compatibility claims directly.

## Evidence Boundary

Compatibility evidence is unchanged from v1.1.0 and was not re-run for this
release. Codex and Claude Code hold controlled runtime-loading results for
`codex-cli 0.145.0` and Claude Code `2.1.218`; the machine that prepared this
release reports `0.146.0` and `2.1.220`, and no claim is made about those.
GitHub Copilot remains Secondary with no runtime probe.

Release readiness records are written in Chinese from this release onward. They
are internal audits rather than published artifacts. Release notes such as this
file stay in English because they become the GitHub Release body. Where an
English document cites a Chinese audit, it carries the conclusion in English
rather than only a link.

## Upgrade From v1.1.0

No action is required. Nothing in the standard, the templates, the adapters, or
the adoption mapping changed.

The full release audit is recorded in `docs/releases/v1.1.1-readiness.md`,
which is written in Chinese.
